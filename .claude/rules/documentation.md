# Documentation

- Don't hard-wrap prose in markdown files. Let lines run their natural length and rely on the reader's word wrap settings or rendered output. Hard-wrapped prose creates noisy diffs when editing the middle of a paragraph.
- Human-facing documentation (READMEs, guides, anything intended primarily for human readers) should read like it was written by a person, not generated by an LLM. Write naturally and conversationally. Avoid the overly structured, exhaustively enumerated style that reads like a reference manual. This doesn't apply to AI-facing documentation like CLAUDE.md, rules files, or system docs where information density matters more than voice.
- Consider the target audience's technical level. Don't over-explain things the likely reader already knows, and don't under-explain things they might not. As an open source game, potential contributors range from experienced developers to long-time players learning to work with code for the first time. Aim for the middle of that range - don't assume deep C++ expertise, but don't try to teach programming fundamentals either.
